# Model Sync

Metis ships a small tool that keeps shared Pydantic models consistent across the six MedEd services without a published pip package. Canonical definitions live in JSON Schema; per-service Pydantic models are generated and committed.

---

## Why not a shared package?

Considered and rejected for now:

| Option | Why not |
|---|---|
| **Shared pip package** (`meded-models`) | Adds release/versioning overhead; pinning across 6 repos drifts |
| **Git submodule** | Submodules confuse contributors and break shallow clones |
| **Copy-paste** | Drift is silent and corrosive |
| **Code generation (chosen)** | One source of truth; generated files are reviewable in PRs; each service stays self-contained |

Trade-off: schema changes require running `sync.py` and committing to every project. CI could enforce this with `--validate` (not yet wired).

---

## Source of truth

```
metis/shared/
├── models/
│   ├── clinical.schema.json     # CodeableConcept, Condition, Medication, Allergy
│   └── context.schema.json      # PatientContext, EncounterContext, ScriptLine, etc.
├── templates/
│   └── python/
│       └── pydantic_model.py.j2 # Jinja2 template
└── sync.py                      # The CLI
```

JSON Schema (draft-07). Each definition becomes one Pydantic class.

---

## Per-project consumption

Each project receives a `_generated/` directory:

| Service | Generated path | Models |
|---|---|---|
| Oread | `synpat/src/models/_generated/` | `CodeableConcept`, `Condition`, `Medication`, `Allergy`, `PatientContext` |
| Syrinx | `synvoice/models/_generated/` | + `EncounterContext`, `ScriptLine`, `InjectedError` |
| Mneme | `synchart/backend/src/models/_generated/` | same as Oread |
| Echo | `echo/src/models/_generated/` | + `EncounterContext`, `EncounterSummary`, `ScriptLine`, `InjectedError` |

Each generated file has a header:

```python
"""
GENERATED BY METIS - DO NOT EDIT DIRECTLY
Generated at: 2026-04-03T07:30:00
Source: metis/shared/models/

To modify, edit the JSON Schema and run: python metis/shared/sync.py
"""
```

## Workflow

### Modify a shared model

```bash
# 1. Edit the JSON Schema
$EDITOR metis/shared/models/clinical.schema.json

# 2. Regenerate for all projects
cd metis/shared
python sync.py --project all

# 3. Each project has updated files in src/models/_generated/
# Commit those alongside the schema change

# 4. Bump version if it's a breaking change
```

### Just regenerate one project

```bash
python sync.py --project oread
```

### CI-friendly validation

```bash
python sync.py --validate        # exits non-zero if generated files are stale
```

### Dry run

```bash
python sync.py --dry-run         # show what would be written
```

## Schema conventions

- **Cross-file refs:** `clinical.schema.json#/definitions/Condition` works
- **Local refs:** `#/definitions/CodeableConcept` works
- **Enums:** `"enum": ["active", "resolved", "inactive"]` → Pydantic `Literal[...]`
- **Optional fields:** anything not in `required` becomes `Optional[T] = None`

Type mappings (from `sync.py`):

| JSON Schema | Python |
|---|---|
| `string` | `str` |
| `integer` | `int` |
| `number` | `float` |
| `boolean` | `bool` |
| `array` | `list[T]` |
| `object` | `dict` (or named class if `$ref`) |

---

## When NOT to use this tool

- **Service-private models** — keep those in the service's own `src/models/`. Only schema *shared across services* belongs in `metis/shared/`.
- **API request/response DTOs** that only one service uses — those are private contracts.
- **Athena content schemas** (conditions, frameworks) — those live in Athena and aren't shared this way.
