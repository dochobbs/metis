## Project Overview

**Metis** is the unified portal for the MedEd platform. It provides:
- Single entry point web dashboard
- Shared Supabase authentication
- Model sync tooling across projects
- Shell scripts for orchestration

Named after Metis, Greek goddess of wisdom and counsel.

## Portal Architecture

### Routes
| Route | Component | Backend Proxy |
|-------|-----------|---------------|
| `/` | Dashboard | - |
| `/login` | Login | - |
| `/oread/*` | - | http://localhost:8004 |
| `/syrinx/*` | - | http://localhost:8003 |
| `/mneme/*` | - | http://localhost:8002 |
| `/echo/*` | - | http://localhost:8001 |

### Vite Proxy Configuration (Updated February 2026)

```typescript
// portal/vite.config.ts — actual current config
'/api/oread'  → localhost:8004, rewrite to '/api'
'/api/syrinx' → localhost:8003, rewrite to '/api'
'/api/mneme'  → localhost:8002, rewrite to '/api'
'/api/echo'   → localhost:8001, rewrite to ''     ← Echo has NO /api/ prefix
```

**Gotcha:** Echo routes (`/question`, `/feedback`, `/debrief`, `/health`) lack `/api/` prefix. The Echo proxy rewrites to `''` (empty string), not `'/api'`. All other services rewrite to `'/api'`.

### Cross-Service Integration (February 2026)

Dashboard.tsx now makes **real API calls** instead of `window.open()`:

| Button | Flow |
|--------|------|
| **Generate** | `POST /api/oread/generate` → stores patient in Oread's memory |
| **Open in Mneme** | Fetches patient from Oread → `POST /api/mneme/import/oread/json` → opens Mneme |
| **Send to Syrinx** | Fetches patient from Oread → `POST /api/syrinx/patients/import` → opens Syrinx |
| **Echo chat** | Fetches `PatientContext` from Oread `/context` endpoint → `POST /api/echo/question` |

See **`docs/INTEGRATION.md`** for the full cross-service integration guide, architecture diagrams, error troubleshooting, and test procedures.

## Model Sync System

### Purpose
Keep shared Pydantic models consistent across projects without a shared pip package.

### Workflow
1. Define canonical models in `shared/models/*.schema.json`
2. Run `python sync.py --project all`
3. Generated code appears in each project's `src/models/_generated/`
4. Commit generated files to each project

### Schema Format
```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "definitions": {
    "Condition": {
      "type": "object",
      "required": ["id", "display_name"],
      "properties": {
        "id": { "type": "string" },
        "display_name": { "type": "string" },
        "code": { "type": "string" },
        "status": { "enum": ["active", "resolved", "inactive"] }
      }
    }
  }
}
```

### Sync CLI
```bash
python sync.py --project all      # Generate for all projects
python sync.py --project oread    # Generate for one project
python sync.py --validate         # Check if models in sync (for CI)
python sync.py --dry-run          # Show what would be generated
```

### Generated Output
Each project receives files in `src/models/_generated/`:
```python
"""
GENERATED BY METIS - DO NOT EDIT DIRECTLY
Generated at: 2025-12-29T07:30:00
Source: metis/shared/models/

To modify, edit the JSON Schema and run: python metis/shared/sync.py
"""

from pydantic import BaseModel
from typing import Optional
from datetime import date

class Condition(BaseModel):
    id: str
    display_name: str
    code: Optional[str] = None
    status: str = "active"
```

## Standalone vs Ecosystem Mode

Each project detects mode via `METIS_MODE` environment variable:

```python
# In each project's config.py
import os
mode = os.environ.get("METIS_MODE", "standalone")

if mode == "ecosystem":
    # Restricted CORS, required auth, progress tracking
    cors_origins = ["http://localhost:3000"]
    auth_required = True
else:
    # Permissive CORS, optional auth
    cors_origins = ["*"]
    auth_required = False
```

## Integration with MedEd Platform

### Data Flow
1. User logs into **Metis Portal** via Supabase
2. Portal provides unified navigation to all tools
3. JWT token passed to embedded tools
4. Each tool validates against shared Supabase
5. Progress tracked in `progress_records` table
